# 150h MajesticVoice：数据合成、82M 两阶段训练与长文本效果

更新：2026-09-24。训练已完成，最终450条常规评价与本次30条长文本A/B音频均完成评分，无评价失败。

**结论：加入约50小时多句长文本合成数据后，长上下文导致首句缩短的现象有所减轻，但没有消失。** 与之前的100h、20轮长样本加权模型相比，中文首句预测时长变化的中位数从−9.52%改善到−7.47%，混读从−8.65%改善到−5.17%。常规识别指标接近；音色相似度和自动音质评分没有全面提升，不能概括成所有方面都更好。

本报告按“用了什么数据 → 怎样合成 → 怎样训练 → 效果如何”说明。此前7.48M学生蒸馏是另一个实验，本轮训练的是官方通用 **Kokoro-82M v1.0**。

## 3. 新增50h如何合成与筛选

### 3.1 文本先过前端与长度检查

流程为：原始完整转写 → 文本筛选 → Kokoro音素化和去重 → VoxCPM2整段生成 → ASR与声学质检 → 每条文本选一个候选。

文本要求至少三个有内容的完整句子，句数按保守标点规则判断，并非语法解析。粗估时长17–45秒；再用实际Kokoro前端检查最多510个有效音素，加首尾标记后最多512。VoxCPM2按实际tokenizer计算文本、参考文本和参考音频的上下文开销，并预留1,000生成token，总预算不超过4,096。

前端与训练保持一致：通用v1.0对应的Misaki中文前端，中文/混读中的英文片段显式走英文G2P。不是复用LITs音素ID，也不靠截断长文本满足限制。

### 3.2 生成模型与参考音色

- 模型：VoxCPM2；通过四个独立单GPU服务运行，每个服务8个请求槽。
- 中文和混读使用之前批准的中文参考，复制为新数据目录中的`reference/zh.wav`。
- 英文使用之前选定的英文参考候选72003，复制为`reference/en.wav`；英文合成与音色质检都使用英文参考。
- 一次请求生成完整段落；每条候选按文本ID与attempt设置可追溯seed。
- 输出保留48kHz原始WAV，并重采样得到单声道24kHz PCM16训练音频。不会通过补静音、截音频或分句拼接来达到时长目标。
- 中文/英文每条最多4个候选，混读最多8个；每轮生成2个。某轮结束后，从已通过全部门槛的候选中选分数最高的一个；只计入这一个样本的实际时长。

候选排序分数为`2×WavLM相似度 + CAMP相似度 + 0.25×DNSMOS OVRL`。排序只在已经过所有硬门槛的候选之间进行。

### 3.3 质检门槛

ASR使用Qwen3-ASR-1.7B、空上下文，不把目标文本作为识别提示；合成质检的ASR输出上限为1,024 token。

| 检查 | 通过条件 |
|---|---|
| 实际音频长度 | 15–45秒；本批最终实际15.04–31.84秒 |
| 中文内容 | CER≤2%；若带声调拼音完全一致，允许原始CER≤5%的同音字例外 |
| 英文内容 | WER≤2%，同时CER≤2% |
| 混读内容 | 英文部分WER=0，中文部分CER≤2% |
| 音色相似度 | WavLM≥0.70，CAMP≥0.68 |
| DNSMOS | OVRL≥3.3，SIG≥3.5，BAK≥3.8 |
| 削波 | 幅值接近满幅的采样比例≤0.0005，即0.05% |
| 有效发声 | 活跃帧比例≥55% |
| 静音 | 开头≤0.4秒，结尾≤0.6秒，最长内部静音≤0.8秒 |

静音按20ms帧和相对RMS阈值检测，是工程筛选指标。训练音色指标及DNSMOS均是自动模型评分，不代表人工逐条听审。

实际入队11,180条文本，共30,000个候选：15,844个候选通过、14,156个淘汰，最终选取9,503条唯一文本。**候选通过数不等于最终数据条数**；同一文本的多个通过候选只选一个。

最终审计重新检查所选音频时长、词表/上下文限制、质检门槛及历史文本重叠，结果通过。依据：[合成配置](evaluation/combined150h/synthesis_config.json)、[最终合成审计](evaluation/combined150h/synthesis_final_audit.json)。实现位于[`data_generation/majestic_long/`](../data_generation/majestic_long/README.md)。

## 4. 两阶段具体怎么训练

### 4.1 Stage 1：学习对齐与目标音色重建

从官方82M预训练权重开始，训练文本对齐器、文本编码器、声学style编码器、波形decoder和判别器。BERT与韵律预测分支暂不更新，JDC音调提取器冻结。

整句Mel与音素用于对齐，求最大单调路径MAS；训练中混用软对齐与MAS。根据真实音频提供的F0、能量和style重建对应波形。

生成器损失为`5×Mel重建 + WavLM感知 + GAN + 文本交叉熵 + 单调对齐项`。Stage 1共4轮、3,952步，完成后保存`stage1_final.pth`。

### 4.2 Stage 2：预测时长、F0与能量，再联合优化

加载本轮Stage 1结果，用已训练声学编码器初始化韵律编码器的共享特征，韵律输出头围绕原生韵律向量初始化；重新创建优化器。

前1,000步训练BERT、bert_encoder、predictor及predictor_encoder，decoder冻结但保留输入梯度。之后加入声学编码器、decoder、可学习voice及波形判别器联合训练；对齐器、文本编码器、JDC继续冻结。

时长以MAS结果为监督，结合时长L1与占用BCE；F0和能量以真实音频特征为监督。损失为`5×Mel + WavLM + 联合阶段GAN + duration + 20×duration_BCE + F0 + energy`，实现内F0项另除以10。

**长句完整参与对齐和时长监督，但波形重建仍随机裁剪最多400个Mel帧，约5秒。** 本次没有把解码器的训练裁剪窗口扩到30秒；训练波形展开采用真实MAS时长，推理则采用预测时长。这些差异仍可能限制长段落效果。

Stage 2共20轮、19,760步，最终累计23,712步。两个阶段均完成，没有把预检权重接到正式训练中。

### 4.3 音色与长样本采样

联合阶段开始时，用固定96条训练音频提取编码器均值，初始化一个256维可学习voice。每卡16条中随机一半使用该voice，另一半使用逐句参考编码器；时长、F0/能量及decoder条件保持同一分配。导出的`majestic.pt`是学到的voice，不是简单用参考均值替代。

Stage 2沿用之前的长样本加权：每种语言内部，按音素数选最长20%作为长池。第1–12轮权重1；第13–17轮依次提高为1.4、1.8、2.2、2.6、3；第17–20轮保持3。权重3时，长池预期占该语言抽样数约42.9%。

这是语言内有放回加权抽样，各语言每轮抽样条数保持原配比，每轮仍988步；不意味着每个样本都恰好被训练一次。新合并集长池门槛为中文300、英文142、混读325音素，第20轮实际长池抽样占比分别约43.15%、42.70%、43.26%。

### 4.4 关键超参数与运行保障

| 项目 | 配置 |
|---|---|
| 并行 / batch | 四卡DDP，每卡16，全局64；按时长分桶 |
| 精度 | BF16；文本编码器FP32 |
| 优化器 | AdamW，betas=(0,0.99)，eps=1e-9 |
| 学习率 | BERT 1e-5；主干5e-5；辅助/判别器/voice 1e-4 |
| 调度 | 每阶段500步warmup；预算后20%线性衰减至基础学习率的0.1 |
| weight decay / 梯度裁剪 | 常规1e-4，voice为0；梯度范数上限5 |
| 评价 | 阶段第100步冒烟；每1,000步及阶段结束做常规评价 |
| 可恢复状态 | 模型、优化器、逐rank随机状态和buffer、数据哈希、下一批位置 |

训练前对最长31.84秒、最多510音素的128条样本进行了两个阶段各2步的四卡batch16预检，包含Stage 2联合训练与voice梯度，均通过。训练、评估源码和两个阶段配置分别冻结到运行目录。详见[预检报告](../reports/combined150h_preflight.json)、[Stage 1配置](evaluation/combined150h/config.json)、[Stage 2配置](evaluation/combined150h/config_stage2.json)。

## 5. 效果：450条常规评价

对照模型是此前**旧100h、20轮长样本加权最终模型**，即`majestic_s2_20ep_long_resume6k_20260921`，不是旧10轮baseline或7M学生。新模型使用150h并重新训练两个阶段。

沿用固定中文200、英文200、混读50条文本和分语言参考；双方各自使用学习到的voice。CER/WER是micro，音色与DNSMOS是逐句均值。450条均无评价失败；这套固定评价用于训练期间监测，不等同于独立保留的608条测试集。

| 指标（旧100h → 新150h） | 中文200条 | 英文200条 | 混读50条 |
|---|---:|---:|---:|
| ASR主指标 | CER 0.212% → 0.159% | WER 0.821% → 0.869% | CER 0.089% → 0.089% |
| WavLM音色相似度 | 0.838 → 0.839 | 0.814 → 0.812 | 0.787 → 0.787 |
| CAMP音色相似度 | 0.769 → 0.763 | 0.820 → 0.821 | 0.734 → 0.739 |
| DNSMOS OVRL | 3.476 → 3.452 | 3.369 → 3.347 | 3.456 → 3.437 |

中文识别错误略少，英文WER略高，混读CER持平；音色指标变化较小，三组DNSMOS OVRL均略低。因此常规评价不能支持“150h模型整体音质全面提升”。混读英文/数字词WER在双方均为4.167%，其分母很小，应与整段CER分别理解。

原始结果：[旧100h](evaluation/combined150h/old100h_summary.json)、[新150h](evaluation/combined150h/new150h_summary.json)。这些分数不能代替人工听感，也没有做显著性检验。

## 6. 效果：长文本直接生成对比

### 6.1 与之前相同的输入和检查方法

复用2026-09-22保存的15组文本和音素：每种语言4条验证集中音素最多的文本，加1条人工撰写的四句探针。两模型均speed=1、整段生成，不分句、不截断、不插入额外停顿。30条完整音频重新运行相同ASR及音质评分，全部成功。

首句对照保持音素前缀完全一致：同一首句分别单独输入与放入完整上下文，比较模型预测帧数，排除BOS/EOS：

`首句时长变化 = (完整上下文中首句预测帧数 / 单独生成首句预测帧数 − 1) × 100%`

负数表示首句在长上下文中被预测得更短。它是时长模型诊断，**不是人工标注的声学切分或整段真实语速测量**。中文有5组、混读5组；英文验证样本大多为单句，只有四句探针1组能做首句对照。

旧模型重新生成的逐音素时长与2026-09-22保存结果完全一致。本次双方重新评分，表中没有拼接旧报告的ASR/DNSMOS数值；自动评分重新运行可能有小幅差异。

### 6.2 汇总结果

| 指标（旧100h → 新150h） | 中文 | 英文 | 混读 |
|---|---:|---:|---:|
| 平均整段时长，秒 | 15.130 → 15.355 | 13.945 → 13.980 | 17.685 → 17.975 |
| 配对整段时长变化中位数 | +0.76% | 0.00% | +1.98% |
| **首句时长变化中位数** | **−9.52% → −7.47%** | **−6.15% → −2.86%** | **−8.65% → −5.17%** |
| 首句配对数 | 5 | 1 | 5 |
| ASR主指标 | CER 0.478% → 0.478% | WER 0.459% → 0.459% | CER 0.359% → 0.000% |
| CAMP音色相似度 | 0.818 → 0.814 | 0.845 → 0.838 | 0.818 → 0.815 |
| DNSMOS OVRL | 3.485 → 3.503 | 3.485 → 3.440 | 3.498 → 3.496 |

11组首句对照中，**9组向0改善、1组持平、1组变差**。中文5组全部改善；最明显的中文缩短从17.35%减轻至13.00%。四句中文探针从−10.48%改善至−6.50%。

改善并不均匀：一个混读样本仍为−12.50%，另一个从−3.37%变为−5.17%；四句混读探针只从−10.19%改善到−9.17%。因此可以说“本批样本中长上下文时长稳定性改善”，不能说“长文加速已修复”。英文只有一组首句配对，不能泛化为英文总体效果。

整段略变长也可能包含停顿差异，不能单独视为发音速度改善。这个15组探针覆盖168–441音素，不覆盖超过510有效音素的文章、分钟级长音频或分句拼接策略。

## 7. 能得出什么结论，不能得出什么

1. 150h两阶段训练已完成，数据检查、训练预检、最终常规评分和这次长文本评分均通过。
2. 新数据明显增加了多句长输入覆盖；在固定小样本上，中文和混读首句的上下文缩短减轻。
3. 长文本识别指标没有恶化，但常规英文WER和部分音质指标略有退步；不能只挑改善指标判定全面胜出。
4. 两模型虽然都是20轮Stage 2，但新数据更多、更新步数更多（19,760对16,800）、Stage 1和voice也重新训练；不是只改变“新增50h”这一因素的严格消融。
5. 波形训练仍采用约5秒裁剪；更长段落、逐句速度变化和人工停顿/自然度评价还需专门实验。网页默认逐句合成属于另一种推理方式，本次未用它掩盖整段直接生成的问题。

## 8. 模型文件与复现入口
